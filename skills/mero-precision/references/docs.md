# Documentation overlay

Write technical documentation for a reader who must understand it in one pass.

## Classify each passage

- A procedure tells the reader what to do.
- A description explains what a system is or does.

Do not blur the two inside one sentence.

## Procedures

1. Use one instruction per step.
2. Put the condition before the instruction.
3. Put warnings before the dangerous action.
4. State the risk after the warning command.
5. Preserve commands, paths, identifiers, and quoted errors exactly.
6. State how the reader verifies success.
7. State rollback or recovery requirements when failure can cause persistent effects.

## Descriptions

1. Use one topic per paragraph.
2. Introduce one material fact at a time.
3. Use stable terminology.
4. Prefer active voice when the actor matters.
5. State measurable properties instead of adjectives such as “robust” or “fast.”
6. Separate current behavior from planned behavior.

## Language

Use complete grammar. Do not drop articles or conjunctions for terseness.

Remove filler, synonym rotation, decorative clauses, and unsupported ease claims.

Do not impose a hard sentence-length limit when it would damage precision. Split a sentence when it contains multiple independent facts or actions.
